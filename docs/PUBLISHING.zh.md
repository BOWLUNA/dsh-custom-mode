## 当前发布路径

仓库根就是 npm 包。它携带的 `preset/` 是唯一打包预设真源；激活时只补缺失用户文件，并刷新受管代码。仅供预设导入的 `.dshpreset` 归档不会安装设置页。不要恢复旧 `editor/` 子包，也不要再让 npm 用户 clone 第二份预设。

`2.2.6` 在精确候选通过门禁且发布读回前仍是修复候选。源码、本地检查、独立审阅、远端 CI、npm 发布和 GitHub Release 的结果分别记录。

1. 在 `package.json` 固定候选版本，同步两种语言文档及配对记录，记录完整候选 commit。插件版本不镜像宿主版本；只有精确宿主完成适配验证后才改宿主钉定与范围。
2. 跑已登记套件、真实提示词组件合约、翻译与文档守卫、语法检查和真实 npm packlist。打包安装、重启、预设选择、浏览器交互、卸载重装使用隔离 home。中断保存与安装回滚用合成数据验证；发布检查表明确未覆盖的桌面/模型/GPU 边界。
3. 由非作者检查最终 diff 与对应证据。push 已检查分支后读回远端完整 SHA，可用 draft PR 承载审阅；合并默认/生产分支属于另行授权的动作。
4. 沿用 `.github/workflows/release.yml`。与包版本匹配的 `v<package version>` 标签先触发可复用兼容性、浏览器工作流，再发布。指定精确版本的手动 dispatch 仅从 `main` 发布；空参数 dispatch 只检查身份，不发布。不要把既有发布标签挪到另一个 commit，也不要绕过失败门禁。
5. 沿用既有 NPM_TOKEN 或 Trusted Publishing/OIDC 配置。当前工作流先检查并传入已有 NPM_TOKEN；未配置 token 时，npm 可使用既有 OIDC 发布者连接。不读取或改写秘密、发布权限、审批或全局发布策略。凭据/审批不可用时走正常所有者流程。
6. 读回标签 commit、必经运行结果、精确 npm 版本及 dist 元数据、GitHub Release 资产，核对下载散列。命令已启动、npm 处于暂存发布、本地测试成功，都不代表分发完成。

## 包与发布资产

`package.json` 声明运行时白名单、bundle 补丁、浏览器导出和可选宿主 peer，保持一份清单真源。核对真实列表，不手写一份会过期的预期列表：

```sh
npm pack --dry-run --ignore-scripts --json
```

发布资产沿用 `tools/release-assets.py` 入口，产出 npm 插件包、仅供预设导入的归档和覆盖这两个资产的 `SHA256SUMS`。只在隔离输出目录运行，manifest 必须指向真实验收过的来源宿主，资产检查绑定同一候选 commit。官方宿主安装、用户 home、缓存、凭据与测试环境不应进入资产。

clone 后的 `./install.sh --profile web` 保留源码链接开发方式。它离线准备/校验新包，并对实际已安装旧包做回滚快照。已有用户提示词、元数据与组成不变，受管代码单独留恢复快照。替换失败通过真实宿主包操作恢复，不把旧清单复制到另一个 node_modules 状态上冒充回滚。回滚不完整时保留打印的事务目录。普通注册表用户可直接按 README 固定版本安装。

## 历史发布说明

以下事实解释旧故障；当时的命令、API 假设与凭据建议不是当前配置指令。完整版本历史保留在 Git 和 [MEASUREMENTS.zh.md](MEASUREMENTS.zh.md)。

- 1.10.0 之前根目录是 private 包装器，真正 npm 包位于 `editor/`，导致第三方探测器混淆并要求两份预设。单根包已取代该结构。
- 旧 `0.1.6-alpha.*` 版本线镜像宿主并使用 alpha 标签；1.0.0 起插件独立使用裸稳定版本号。不要把历史 alpha dist-tag 或例子当成当前安装命令。
- 旧实测发现冷却/缓存及重复 `minimumReleaseAgeExclude` 会选中或拒绝意外版本。精确选择仍需策略/兼容性接纳与版本读回，不意味着绕过所有包管理策略。
- 早期记录建议过会话登录、Automation token、改标签和手动 Release API，那是特定故障的绕过方案。当前沿用既有发布门禁与已配置认证，不照抄历史凭据/权限教程。
- 历史社交预览 API 限制、目录数量与截图选择只代表记录当时。修改公开元数据前重新核对，不将其当成当前 API 合约或必做发布动作。
