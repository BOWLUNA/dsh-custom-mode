结果绑定精确安装与生成的源码快照。2.2.6集成检查在 Windows、Node `24.21.0`、DSH `0.2.1-rc.2` 上通过 **18套件/1139检查**。安装器覆盖部分写入、独占发布、并发文件、回滚失败与填模板前恢复，非作者复核重现了发布文件的失败边界。这些是本地/组件检查，不是完整桌面对话。

最终生产UI代码还在隔离Windows `0.2.1-rc.2` 宿主上通过Linux Chrome检查：模式选择器与74项浏览器检查通过。中文/英文配合真实明/暗主题在1440、720、480像素下通过，包含长助手名/历史标签与可见原生菜单。独立交互探针注入了延迟POST、后续GET失败和应用失败响应；重试读取不重复保存，重试生效发送真实sync请求。这些注入响应不代表生产中自然发生的故障。宿主toolbar按钮与专用Language选择器的背景不同；插件保留原生原子，不宣称二者外观完全相同。

2026-10-27 公开 npm 宿主标签为 `latest=0.2.1-rc.2`、`next=0.2.1-rc.4`、`alpha=0.2.2-alpha.2`。这三个精确宿主已完成集成单元、打包安装和启动检查；rc.4与alpha.2还各通过真实市场行10项检查，包含开启/保存/关闭/保存且预设健康。alpha要求Node `>=24.9`。

真实组件门禁使用 Cordis/SystemPrompt，以及存在时官方 WorkingDirectoryService 的构造、生命周期与ensure行为，只有会话/文件系统投影为合成。它检查旧默认文本、自定义suffix、目录变化/修复与含花括号路径，不改写用户文件：

```sh
node tools/prompt-contract-check.mjs --host-install /path/to/exact-host
```

这个组件命令不启动agent loop或模型服务。另一次真实 `0.2.1-rc.2` Web会话完成了新建助手→保存提示词→新会话选择→发送首条消息，界面显示 `CUSTOM_MODE_READY`。本机回环合成SSE provider验证了自定义提示词标记和展开后的cwd/model。该会话使用最后纯布局修改之前的修复UI（`client.js` SHA256 `6f7d01b6…`），其提示词/后端运行核心与最终UI一致。最终布局（`ccacb21f…`）有上文独立浏览器检查，没有再完整重跑一次首次会话。响应来自合成provider，不是商业模型；第二次请求被fixture的标记规则拒绝，不计作另一次成功首轮。测试宿主由人工终止，不记为优雅退出0。

Electron桌面端、商业模型和GPU执行不在这些证据内。当前通道CI使用Node24；旧宿主保留Node20单元腿和Node24运行门禁。发布门禁必须绑定最终commit；发布和资产读回与这些实测范围分别记录。

## 发布门禁与复现

现有发布工作流要求两个可复用的兼容性与浏览器工作流先通过，然后发布；另要求标签与包版本精确匹配，以及已有 npm 发布者配置。本地测试成功不能证明远端 CI、注册表发布或 GitHub Release 已完成。缺失的 npm 审批或凭据必须通过正常发布者流程处理。

使用精确官方宿主，并在源码树外新建证据目录：

```sh
node tools/compat-check.mjs --host-install /path/to/exact-host --out /path/to/new-evidence --port 32110
node tools/runtime-check.mjs --host-install /path/to/exact-host --out /path/to/new-evidence --browser /path/to/chrome --port 32110 --cdp-port 9229 --network-guard ./tools/loopback-test-guard.mjs
```

工具使用独立目录与合成提示词。不要对当前用户正在使用的 profile 运行，也不要把凭据、提示词或历史复制到证据中。可选Node回环守卫作用于测试进程中被覆盖的net/fetch路径，不是系统级网络隔离，也不约束外部程序。依赖预先从官方注册表安装。保持单个浏览器页面，并按机器资源执行内存预算。

发布附件只包含白名单插件包、仅供预设导入的归档与 `SHA256SUMS`，不包含宿主安装、用户状态或验收环境。安装前核对下载附件的哈希。`.dshpreset` 附件不能替代设置页插件的安装。
